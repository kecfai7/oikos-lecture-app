#### Slide 12: File Streaming vs. File Mirroring
*   **Visual Cue:** A high-contrast comparison diagram showing local hard drive space usage under Streaming (0MB) versus Mirroring (100% duplicate).
*   **Slide Text:**
    *   *File Streaming:* Virtual projection of cloud files.
    *   *File Mirroring:* Physical synchronization and duplication of files on local drive.
*   **Professor's Script:**
    "When integrating Google Drive into your operating system, you face a critical architectural decision: File Streaming or File Mirroring. Do you project your files virtually, or do you duplicate them physically? Let us look at the trade-offs of each approach."

#### Slide 13: File Streaming - Virtual Projection with 0MB Local Cost
*   **Visual Cue:** An abstract projection graphic, showing cloud servers beaming folder trees down to a laptop without consuming its local storage.
*   **Slide Text:**
    *   *Mechanism:* Files are downloaded on-demand and cached temporarily.
    *   *Local Footprint:* Virtually zero hard drive space consumed.
    *   *Dependency:* Requires active, stable internet connection for real-time access.
*   **Professor's Script:**
    "File Streaming is a masterpiece of resource efficiency. It acts like a virtual hologram of your cloud drive. Your computer displays the entire file directory, but the physical bytes stay in the cloud. They are only fetched when you double-click them. This frees up gigabytes of local storage, though it requires a stable internet link."

#### Slide 14: File Mirroring - Offline Redundancy and Local Storage Impact
*   **Visual Cue:** A double-arrow icon showing folders synchronized in absolute symmetry between local SSD and cloud servers.
*   **Slide Text:**
    *   *Mechanism:* Complete 1-to-1 duplication of folders on both local drive and cloud.
    *   *Benefit:* True offline access. Files are instantly editable without internet.
    *   *Cost:* High local storage overhead.
*   **Professor's Script:**
    "File Mirroring is the fallback option for absolute redundancy. It copies every byte from the cloud directly onto your physical hard drive. It is perfect for field engineers or travelers who need uninterrupted offline access. However, it is resource-heavy, and your local hard drive capacity will be highly constrained."

#### Slide 15: Folder Color Coding
*   **Visual Cue:** A grid of custom folders in various primary and secondary colors, where urgent folders are bright red and reference archives are calm blue.
*   **Slide Text:**
    *   *Visual Hierarchy:* Assigning specific colors to represent urgency or content types.
    *   *Efficiency:* Color-coded folders speed up visual identification by up to 3x.
*   **Professor's Script:**
    "Now let us talk about folder taxonomy. A sea of identical gray folders is a design failure. By introducing standard color-coding—such as bright red for active projects, green for financial logs, and blue for reference archives—we exploit pre-attentive visual processing, speeding up folder retrieval by up to three times."

#### Slide 16: The Art of Chronological Naming
*   **Visual Cue:** A slide showing raw, poorly named files ("draft_v2.docx") morphing into perfectly sorted chronological names ("20260814_Syllabus.docx").
*   **Slide Text:**
    *   *SOP Rule:* Prefix files and folders with the YYYYMMDD date structure.
    *   *Result:* Perfect, automated chronological order, independent of system defaults.
*   **Professor's Script:**
    "Standard Operating Procedure Rule Number One: Name your folders and files starting with `YYYYMMDD`. This simple cryptographic discipline prevents files from getting jumbled, ensuring they automatically sort themselves in perfect chronological order, bypassing the chaos of default OS sorting."

#### Slide 17: Web-Native Velocity: docs.new

*   **Professor's Script:**

#### Slide 18: Beyond File Names: Smart Search Operators
*   **Visual Cue:** A clean visual search bar displaying advanced operators: `type:pdf owner:me "final budget"`.
*   **Slide Text:**

Use `type:pdf` to narrow down extensions, `owner:me` to filter your creations, or enclose phrases in quotes to scan deep inside document body text. This turns a clumsy directory search into an exact science."

    "Do you still have team members manually transcribing text from scanned PDFs or photos? That is a waste of human intellect. Google Drive has a native OCR engine. Simply right-click any image or scan, select 'Open With Google Docs', and watch as the system extracts the dark, non-searchable data into editable text in seconds."
