*   **Professor's Script:**
    "Welcome to Section Two. Every great magic has a physical cost. To wear the crown of the OS Shell, the Google App must wear a massive, heavy suit of armor. Let us deconstruct the 1.2GB memory footprint."

#### Slide 12: The WebView2 Architecture
*   **Visual Cue:** An architectural blueprint showing the Chromium WebView2 engine layered inside the desktop application wrapper.
*   **Slide Text:**
    *   *The Core Engine:* Microsoft WebView2 (Chromium-based).
    *   *The Shortcut:* Running a hidden, headless browser instance constantly in the background.
*   **Professor's Script:**
    "Why is a simple search bar so heavy? Because under the hood, it is not a simple app. Google uses Microsoft's WebView2 engine—which is essentially running a hidden, headless Chromium browser in the background. #### Slide 13: The 1.2GB RAM Baseline
*   **Visual Cue:** A scale balance. On one side, a simple text bar; on the other, a heavy 1.2GB weight tilting the scale down.
*   **Slide Text:**
    *   *Baseline Cost:* ~1.2GB of RAM consumed constantly.
    *   *Sub-processes:* Headless GPU rendering, network listeners, and local file scanners.
*   **Professor's Script:**
    "This headless browser setup demands a baseline of 1.2 gigabytes of RAM at all times. The moment your computer boots, before you even type a single letter, 1.2GB of your system's memory is locked away. It is a heavy armor—powerful, but incredibly resource-intensive."

#### Slide 14: Resource Collision in Low-RAM Environments
*   **Visual Cue:** A visual simulation showing an 8GB RAM memory bar colored mostly in red (Danger), contrasting with a 32GB RAM memory bar colored in green (Safe).
*   **Slide Text:**

    *   *32GB Workstations:* Negligible impact, smooth multitasking.
*   **Professor's Script:**
    "If you are running a high-end 32GB workstation, 1.2GB is a drop in the bucket. But if your students or employees are on standard 8GB laptops, losing 1.2GB of RAM just for a search bar causes 'memory thrashing.' The computer starts swapping RAM to the hard drive, resulting in system lag."

#### Slide 15: 📊 Python Resource Impact Simulation
*   **Visual Cue:** A clean presentation of python code output showing the calculated system degradation on different RAM configurations.
*   **Slide Text:**
    *   *8GB Laptop:* Impact Score = **26.7%** (Status: **Caution/Lag Risk**)

#### Slide 16: The Battery Drain Paradox
*   **Visual Cue:** A battery icon showing a fast-discharging yellow lightning bolt representing background browser activities.
*   **Slide Text:**
    *   *Background execution:* Headless Chromium sub-processes never sleep.
    *   *Battery Impact:* Up to 15% faster discharge rates on portable laptops.
*   **Professor's Script:**
    "Because the headless sub-processes never sleep—constantly listening for hotkeys, scanning local directories, and maintaining cloud connection sockets—it acts as a constant drain on portable laptop batteries. #### Slide 17: GPU Acceleration vs. CPU Overload
*   **Visual Cue:** A split diagram showing CPU tasks (sequential blocks) versus GPU acceleration (parallel matrices) for UI rendering.
*   **Slide Text:**

    *   *CPU Fallback:* Occurs on low-end hardware, leading to typing latency.
*   **Professor's Script:**
    "To make the search interface feel 'butter-smooth,' Google utilizes hardware GPU acceleration. On low-end corporate laptops, this creates noticeable typing latency—the text lagging behind your actual keystrokes."

#### Slide 18: WebView2 Security Sandboxing Limits
*   **Visual Cue:** A transparent glass wall containing a glowing file folder, representing sandbox boundaries.
*   **Slide Text:**

*   **Professor's Script:**
    "WebView2 is sandboxed by default for security. It cannot touch your system files. To bypass this, Google had to build a 'local helper service' that sits outside the browser window and handles the actual file fetching. This bridge between the sandbox and the local system is a prime target for potential exploits."

#### Slide 19: The "Heavy Armor" Philosophical Lesson

*   **Slide Text:**
    *   *The Lesson:* "He who desires to rule the OS must bear the weight of the OS."
    *   *IT Wisdom:* Never adopt a software solution without auditing the physical resource cost.
*   **Professor's Script:**
    "There is a deep IT lesson here: 'He who desires to rule the OS must bear the weight of the OS.' As architects, you must never fall in love with a software's features without auditing its physical resource costs. A beautiful tool that slows down your system is not an asset; it is a liability."

#### Slide 20: Section 2 Summary
*   **Visual Cue:** Summary slide showing a blueprint diagram of the WebView2 memory allocation.
*   **Slide Text:**
